# Environment & Deployment

Separate development and production configuration. Never hard-code MongoDB URI, auth secrets, storage credentials or private API keys.

Production checklist: HTTPS, secure auth, rate limiting, error logging, backups, media storage, sitemap/robots, protected admin, production build, responsive QA.

## Free deployment

| Piece | Service | Free allowance |
| --- | --- | --- |
| Site + API | Render web service (`render.yaml`) | 512 MB RAM, 750 hours/month; sleeps after 15 min idle |
| Database | MongoDB Atlas M0 | 512 MB |
| Photos | Cloudinary (no card needed) | 25 monthly credits (1 credit = 1 GB stored or 1 GB delivered) |
| Address | `<name>.onrender.com` | A custom domain is the only paid part, when wanted |

### 1. Code on GitHub

Push the repository to GitHub (private is fine). `.env` is git-ignored and must stay that way.

### 2. MongoDB Atlas

1. Create a free **M0** cluster.
2. **Database Access** → add a user with a password.
3. **Network Access** → allow `0.0.0.0/0` (Render's free plan has no fixed IP).
4. **Connect → Drivers** → copy the string and add the database name: `mongodb+srv://<user>:<pass>@<cluster>.mongodb.net/moh?retryWrites=true&w=majority`.

### 3. Cloudinary

1. Sign up at cloudinary.com (free plan, no card).
2. Console → **Settings → API Keys** → copy the **API environment variable**: `cloudinary://<api_key>:<api_secret>@<cloud_name>`. Replace `<your_api_secret>` with the revealed secret. This is `CLOUDINARY_URL`.

The server already resizes every photo to WebP with sharp, so files are stored and delivered as-is; no Cloudinary transformations are used. `MEDIA_BASE_URL` is set automatically.

*Alternative:* any S3-compatible bucket (e.g. Cloudflare R2, which needs a card on file) with `STORAGE_DRIVER=s3` and the `S3_*` variables from `.env.example`.

### 4. Render

1. **New → Blueprint** → choose the repository. Render reads `render.yaml`.
2. Fill in the values it asks for: `SITE_URL`, `MONGODB_URI`, `CLOUDINARY_URL`. `JWT_SECRET` is generated by Render.
3. Deploy. On first start the server adds the confirmed courses and settings to the empty database.
4. Once the service URL is known, make sure `SITE_URL` matches it exactly (canonical URLs, sitemap and Open Graph use it).

### 5. The admin account

The admin is never created over the web. From your own computer, point the script at Atlas for one command (PowerShell):

```powershell
$env:MONGODB_URI = "<the Atlas connection string>"
npm run create-admin -- owner@example.com "a long strong password"
Remove-Item Env:MONGODB_URI
```

Values already in the shell take priority over `.env`, so the local `.env` stays untouched. Running it again with a new password is how the password is reset. Then sign in at `<SITE_URL>/admin`.

### 6. Keep it awake and get found

- The free service sleeps after 15 minutes without visitors and takes 30–60 s to wake. Add a free **UptimeRobot** HTTP monitor on `<SITE_URL>/api/health` every 10 minutes; one always-on service uses ~744 of the 750 free hours.
- **Google Search Console** → add the site → submit `<SITE_URL>/sitemap.xml` → request indexing of the homepage.
- **Google Business Profile** with the same name, address and phone as the site, linking to it. This drives local searches ("music classes Nashik Road") far more than the website alone.

### Limits to know

- Render's free disk is temporary; that is why photos must use Cloudinary (`STORAGE_DRIVER=cloudinary`).
- Atlas M0 has no automatic backups; export the database occasionally (`mongodump`) or move to a paid tier once the site is live.
- Moving to Render's paid plan later removes the sleep; nothing else changes.
